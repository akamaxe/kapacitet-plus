# Versions of the project's own virtual environment (.venv), resolved 2026-10-09.
#
# Until then this file pinned whatever happened to be in the base Anaconda env, so that
# installing the project would not disturb the other tools sharing it. That stopped working:
# the base env moved to pandas 3.0, where Copy-on-Write is mandatory, and pandapower 2.14
# writes its results through `DataFrame["col"].values[:]`, so every `pp.runpp` raised
# "assignment destination is read-only" and the whole engine was dead. The base env had also
# drifted to scipy 1.18, which pandapower 2.14 does not support (it requires scipy < 1.14).
#
# The project now has its own environment instead, with a combination every package declares
# as supported:
#
#     python -m venv .venv
#     .venv/Scripts/python -m pip install -c constraints.txt -e ".[dev]"
#
# numpy stays below 2 because pandapower 2.14 and scipy < 1.14 both predate it, which also
# makes the alias shim in `_compat.py` a no-op rather than a dependency.
